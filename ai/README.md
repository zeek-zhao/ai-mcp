> 你（AI）在本仓库承接开发任务时，**先按本文件顺序阅读**，再开始动手。

## 1. 阅读顺序

1. `ai/全局上下文.md` —— 项目背景、不可更改的架构决策、硬性约束。
2. `ai/交付与PR规范.md` —— 分支、提交、PR、自检与回执模板。
3. `docs/00-文档管理规范.md` —— 文档编号、版本、目录、变更记录规则。
4. `docs/planning/项目计划书.md` 与 `docs/planning/里程碑规划.md` —— 范围、约束、里程碑。
5. 当前任务对应的里程碑提示词（见 `ai/实现提示词.md`）与 `docs/operations/任务清单.md` 中对应条目。

## 2. 工作边界

- 只承接当前里程碑/任务范围内的工作，不跨里程碑提前实现。
- 不修改被对接的外部系统；不在 Jenkins 安装插件。
- 不向系统全局 Python/Node 环境安装运行依赖；依赖落在各子服务目录并用锁定文件固定。
- 不写入、不输出、不提交真实凭证；仓库只保留 `*.sample` / `*.template`。
- 文档必须符合 `docs/00-文档管理规范.md`：新增文档先登记台账，补属性表与变更记录。

## 3. 交付要求

- 按 `ai/交付与PR规范.md` 切分支、提交、提 PR，关联对应 Issue 与里程碑标签。
- 完成后按回执模板输出说明；同步更新任务清单状态、必要时更新问题记录与更新记录。
- 遇到选型不可用、约束冲突或需求不清，先在问题记录/Issue 中登记，不要自行更改架构决策。
