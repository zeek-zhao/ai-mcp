## 1. 项目背景

在 Windows 本地构建一套“本地 MCP 套件”，通过一个 GitHub 仓库统一管理多个独立 MCP Server，对接 Gerrit、GitHub、Jenkins、Atlassian（Jira + Confluence）。总纲见 `docs/planning/项目计划书.md`。

## 2. 不可更改的架构决策

- **方案 A**：一服务一独立 MCP Server 进程，禁止合并成单聚合大单体。
- 总控为 PowerShell 全中文交互脚本，菜单分步提示。
- **模型一（传输模型）**：MCP 服务一律由 Host（Cursor / Claude Desktop 等）按需以 stdio 拉起，进程生命周期由 Host 管理；mcpctl 是治理工具（注册表、配置向导、Bootstrap、诊断、探活、遗留进程清理、Host 配置导出），**不后台托管服务进程、不重定向服务 stdout、不做登录常驻**（ADR-005 已取消、ADR-006，2026-11-25）。
- **Jenkins 零侵入**：仅通过 REST API + API Token 远程调用，不在 Jenkins 安装插件或改实例配置。
- **配置集中（ADR-007，2026-11-26）**：四个服务的运行配置集中在仓库根单一文件 `mcp.config.json`（已 gitignore），按 `services.<key>` 分段，字段以 `docs/services/配置字段说明.md` 为权威表、`mcp.config.schema.json` 为结构契约；禁止在服务目录新建配置文件（依赖清单 `requirements.txt` / `package-lock.json` 仍留在各服务目录）。
- 真实凭证仅存本地，绝不提交 Git；仓库只保留统一配置模板 `mcp.config.sample.json` 与结构契约 `mcp.config.schema.json`。

## 3. 受控服务清单

| 代号 | 目录 | 对接系统 | 备注 |
|---|---|---|---|
| A | `mcp-gerrit/` | Gerrit 代码评审 | 评审模型独立封装 |
| B | `mcp-github/` | GitHub / GitHub Enterprise | 本地部署模式，不用官方远程托管端点 |
| C | `mcp-jenkins/` | Jenkins | 零插件，REST API |
| D | `mcp-atlassian/` | Atlassian Jira + Confluence | 一体化，内网 DC/Server |

## 4. 工作硬性约束

1. 所有路径使用仓库相对路径，不写死绝对路径；脚本面向 Windows。
2. 交互文案、菜单、状态、错误提示全部使用中文。
3. 不得在代码、注释、日志、提交信息、文档中写入真实 Token、密码、私钥、内部真实地址。
4. 不修改被对接的外部系统配置；不在 Jenkins 侧安装任何插件。
5. 不向系统全局 Python/Node 环境安装运行依赖；依赖必须落在各子服务目录内并用锁定文件固定。
6. 严格遵循计划书目录结构；新增文件放入对应目录，不随意新建目录。
7. 只实现当前里程碑范围内的内容，不提前实现后续里程碑功能。
8. 文档变更遵守 `docs/00-文档管理规范.md`：台账登记、属性表、变更记录齐全。
