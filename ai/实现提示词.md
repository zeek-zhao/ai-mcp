> **⚠ 2026-11-25 验收纠偏（DEV-008/009/010，Issue #39）**：四服务 StartCommand 已回填并经 `Resolve-McpStartCommand` 归一化（scripts/mcpctl.config.ps1）。后续里程碑（M9/M10 及验收）判定“服务可用”时，以**「StartCommand 已回填且可定位 + 本地配置就绪 + 依赖环境就绪」**三项为准；需真实凭证的连通测试仍标「待执行」并写明前置条件。

## 一、使用说明

1. 每个里程碑对应一个 GitHub Issue，标题格式：`[M<n>] <里程碑名称>`。
2. AI 每次只承接一个里程碑（或其下一个独立子任务），不跨里程碑实现。
3. 每次下发任务时附上：全局上下文、对应里程碑提示词、关联 Issue 编号。
4. 完成后按回执模板输出说明并提交 PR；CI 与评审通过后合并。

## 二、里程碑提示词

### M0 · 仓库骨架与协作规范

```
【本次里程碑】M0 仓库骨架与协作规范（对应 Issue #<编号>）

【任务】
1. 按 docs/planning/项目计划书.md 第 4 节创建仓库目录结构（docs、scripts/lib、四个 mcp-* 子服务目录、.github 目录）。
2. 编写 .gitignore，排除：本地真实配置（*.json 真实配置、.env）、logs/、run.pid、虚拟环境与依赖目录、临时文件。
3. 创建 .github 下：ISSUE_TEMPLATE（feature/bug/task）、PULL_REQUEST_TEMPLATE.md、CODEOWNERS。
4. 创建 CI 工作流 .github/workflows/ci.yml：PowerShell 脚本静态语法解析、模板完整性检查、密钥扫描。
5. 确认 docs/ 与 ai/ 文档骨架齐全；README 写明项目简介与导航。

【产出文件】
- 完整目录结构、模板文件、CI 工作流、文档骨架。

【验收标准】
- 克隆后目录与计划书一致；模板齐全；CI 可触发并在空实现状态下通过。
- 真实配置示例不被 Git 跟踪。

【不要做】
- 不写总控菜单逻辑；不接入任何真实外部系统；不实现启停脚本功能。
```

### M1 · 总控服务注册表

```
【本次里程碑】M1 总控服务注册表（对应 Issue #<编号>）
【前置】M0 已合并入库。

【任务】
1. 编写 scripts/mcpctl.config.ps1，定义服务注册表数组，四个服务条目均包含：服务代号、显示名、子目录名、启动命令（占位）、配置模板路径、本地配置路径、PID 文件路径、日志路径、技术栈标识。
2. 定义全局参数：仓库根目录定位方式、优雅停止超时（默认 15 秒）、菜单语言（中文）。
3. 在 scripts/lib/ 提供读取注册表的基础函数，供后续脚本复用。

【验收标准】
- 四个服务条目字段完整；配置可被 PowerShell 正常解析。
- 新增服务只需追加一条，不改其他逻辑代码。

【不要做】
- 不实现真实启动/停止；不读取外部凭证；不做菜单交互。
```

### M2 · 配置向导

```
【本次里程碑】M2 配置向导（对应 Issue #<编号>）
【前置】M1 已合并入库。

【任务】
1. 实现 scripts/lib/config-wizard.ps1，全中文分步配置向导：
   - 列出四个服务供选择。
   - 本地配置不存在时从 *.sample/.template 复制；已存在时询问“覆盖 / 保留退出”。
   - 按服务逐条录入参数；Token/密码类输入隐藏不回显；写入本地配置。
   - 提供“是否执行连通性测试”入口占位（真实接口在 M5–M8 实现）。
   - 计算配置就绪标记：配置文件存在且必填项非空。
2. 各服务必填参数（可按所选实现微调）：
   - Gerrit：实例地址、认证方式、凭证
   - GitHub：实例地址、PAT、可选组织/仓库范围
   - Jenkins：实例地址、用户名、API Token、可选多实例
   - Atlassian：Jira 地址、Confluence 地址、个人访问令牌、可选空间/项目范围

【验收标准】
- 向导全程中文提示；敏感输入不回显；日志与控制台不输出明文凭证。
- 必填项缺失时标记“未配置就绪”。

【不要做】
- 不实现真实连通性调用；不实现启停逻辑。
```

### M3 · 启停与状态核心

```
【本次里程碑】M3 启停与状态核心（对应 Issue #<编号>）
【前置】M1、M2 已合并入库。

【任务】
1. 实现 scripts/lib/service-utils.ps1：
   - 状态检测：读取 PID 文件、校验进程存在、识别僵尸 PID 并提示清理。
   - 启动：批量只启动就绪服务；未配置跳过并中文提示；单服务异常不阻断其余；成功后写 PID 与日志路径。
   - 优雅停止：通知退出 → 按全局超时轮询等待 → 超时二次确认 → 强制结束；成功后清理 PID。
   - 状态表格输出：服务名、状态、PID、是否就绪、日志位置。
2. 实现 scripts/mcpctl.ps1 主菜单骨架（全中文），先接入启动、停止、查看状态三个入口；其余菜单项占位。
3. 操作日志不含敏感信息。

【验收标准】
- 未配置服务批量启动时被跳过并提示。
- 停止流程遵循“通知 → 等待 → 确认 → 强制”；超时值来自注册表。
- 僵尸 PID 可识别并提示清理。

【不要做】
- 不接入真实外部服务命令；不实现常驻管理；不实现 Bootstrap。
```

## 三、里程碑交接检查点

每个里程碑合并前，AI 需自检并在 PR 中确认：

- [ ] 关联正确的 Milestone 与 Issue 标签。
- [ ] 只包含本里程碑范围内变更，无跨里程碑提前实现。
- [ ] 本地配置、凭证、日志、PID、依赖目录未被提交。
- [ ] CI 全部通过；模板完整性与密钥扫描无告警。
- [ ] 配置项/参数变更已同步 `docs/services/服务接入说明.md`。
- [ ] 新增服务条目已在注册表登记，字段完整。
- [ ] 中文菜单与提示文案完整，无裸露英文占位提示（技术名词除外）。
- [ ] 文档变更已按规范更新台账、属性表与变更记录。
