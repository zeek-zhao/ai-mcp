## 0. 通用前置（四个服务共用）

启动总控：在仓库根执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\mcpctl.ps1`（Windows PowerShell 5.1）或 `pwsh -NoProfile -File scripts\mcpctl.ps1`（PowerShell 7）。下文「菜单 N」均指 `scripts/mcpctl.ps1` 主菜单编号。

| # | 检查项 | 操作 | 期望 |
|---|---|---|---|
| 1 | 运行环境 | `node --version`、`curl --version` | 均有版本输出（GitHub / Jenkins 需要 node；Gerrit 需要 PATH 中的 curl.exe）；Gerrit 需要 Python 3.12+ 常规发行版，Atlassian 需要 Python 3.10+（Microsoft Store 版在受限环境无法创建 venv） |
| 2 | 仓库 | `git status` | 工作区干净，位于 `main` 最新提交 |
| 3 | 依赖环境 | 菜单 5 → 输入 1（仅检查环境） | 四个服务均为「已就绪」；缺失时用菜单 5 → 输入 2（初始化缺失环境，需联网）；GitHub 提示二进制缺失时，先联网运行 `mcp-github\setup-github-mcp.ps1`（Bootstrap 对二进制只检查、不下载） |
| 4 | 统一配置 | 菜单 4 配置向导：仓库根没有 `mcp.config.json` 时选择从模板生成，再逐字段录入真实凭证（敏感字段隐藏输入） | 向导概览显示待验收服务为「已就绪」；`mcp.config.json` 位于仓库根，且 `git status` 不显示它（已被 `.gitignore` 排除） |
| 5 | 服务诊断 | 菜单 1 | 该服务的「配置就绪」=「是」、「依赖环境」=「已就绪」、「启动命令已回填」=「是」 |
| 6 | Host 配置 | 菜单 6 → 直接回车（默认输出到 `%USERPROFILE%\mcp-host-config.json`） | 提示「已导出 Host 配置片段」；文件中四个条目均含 `command` / `args` / `env.MCP_SUITE_CONFIG`，`note` 显示「已就绪」；`command` 不是 `<未回填>` |

字段含义与填写规则见 `docs/services/配置字段说明.md`。

## 1. 把配置片段粘贴到 Host

菜单 6 导出的文件结构如下（路径为示意，实际值以本机导出结果为准；Windows 路径中的反斜杠已按 JSON 规则转义，请整段复制，不要手改）：

```json
{
  "_说明": "……",
  "mcpServers": {
    "mcp-gerrit": {
      "command": "<仓库路径>\\mcp-gerrit\\venv\\Scripts\\python.exe",
      "args": ["<仓库路径>\\mcp-gerrit\\launcher.py"],
      "env": { "MCP_SUITE_CONFIG": "<仓库路径>\\mcp.config.json" },
      "note": "……"
    },
    "mcp-github": {
      "command": "node",
      "args": ["<仓库路径>\\mcp-github\\launcher.mjs"],
      "env": { "MCP_SUITE_CONFIG": "<仓库路径>\\mcp.config.json" },
      "note": "……"
    },
    "mcp-jenkins": {
      "command": "node",
      "args": ["<仓库路径>\\mcp-jenkins\\launcher.mjs"],
      "env": { "MCP_SUITE_CONFIG": "<仓库路径>\\mcp.config.json" },
      "note": "……"
    },
    "mcp-atlassian": {
      "command": "<仓库路径>\\mcp-atlassian\\venv\\Scripts\\python.exe",
      "args": ["<仓库路径>\\mcp-atlassian\\launcher.py"],
      "env": { "MCP_SUITE_CONFIG": "<仓库路径>\\mcp.config.json" },
      "note": "……"
    }
  }
}
```

1. 打开 Host 的 MCP 配置文件（位置以 Host 当前官方文档为准；常见位置：Cursor 为 `%USERPROFILE%\.cursor\mcp.json`，Claude Desktop 为 `%APPDATA%\Claude\claude_desktop_config.json`）。
2. 把导出文件 `mcpServers` 下需要的条目复制进 Host 配置的 `mcpServers` 对象（条目名可按习惯调整；`note` 字段可保留，Host 一般忽略它）。
3. **重启 Host**，使其重新按需拉起服务。

约定：Host 配置中只出现统一配置文件的路径（`env.MCP_SUITE_CONFIG`），不出现任何明文 Token；凭证只保存在仓库根的 `mcp.config.json`。

## 7. 失败排查表

启动器的报错一律输出到 stderr（Host 的 MCP 日志或 mcpctl 探活的「stderr 摘要」中可见），均为中文，且不包含凭证值。

| 现象 | 可能原因 | 处置 |
|---|---|---|
| `统一配置文件不存在：<路径>` | `env.MCP_SUITE_CONFIG` 指向的路径下没有文件：尚未生成配置，或仓库被移动 / 重命名后 Host 配置仍是旧路径 | 菜单 4 生成并录入配置；仓库位置变化后重新用菜单 6 导出并更新 Host 配置 |
| `统一配置不是合法 JSON：<路径>……请检查引号、逗号与括号是否成对。` | 手工编辑破坏了 JSON 格式 | 按提示的行列位置修正；或用菜单 4 重新录入 |
| `统一配置缺少 services.<段> 配置段：……请对照 mcp.config.sample.json 补全` | 该服务的配置段被删除 | 菜单 4 重新录入该服务 |
| `统一配置 services.<段>.<字段>（<中文名>）未填写或仍是占位符，请填写后重试。` | 必填项为空，或仍是模板占位符 `<…>` | 菜单 4 → 录入 / 修改服务配置 |
| `……已在统一配置中禁用（services.<段>.enabled 不是 true），不启动。` | 该服务 `enabled=false` | 需要启用时，在菜单 4 把「是否启用」改为 true；不启用的服务无需验收 |
| `二进制缺失：……`（GitHub） | 尚未下载官方二进制 | 联网运行 `mcp-github\setup-github-mcp.ps1` |
| `上游服务缺失：……下一步：运行 scripts/bootstrap.ps1……`（Jenkins / Gerrit / Atlassian） | 依赖未安装或被删除 | 菜单 5 → 输入 2（初始化缺失环境，需联网） |
| `统一配置 services.atlassian.deployment……只能是 cloud 或 server` | 部署类型取值不合法 | 菜单 4 重新选择部署类型 |
| Host 报 `spawn … ENOENT` 或「系统找不到指定的文件」 | `command` 路径不存在：venv 未创建，或仓库被移动 | 菜单 5 初始化依赖；仓库位置变化后重新菜单 6 导出 |
| `[探活失败] … 未见 initialize 响应。stderr 摘要：…` | 见 stderr 摘要对应的启动器报错 | 对照本表上面的行逐项处置；摘要为空且「进程仍在运行」时多为依赖首次启动较慢，可重试一次 |
| Host 的 MCP 列表里没有该服务，或对话中调不到工具（上下文路径） | ①Host 配置文件位置或 JSON 格式不对；②修改配置后未重启 Host；③未在该 Host 中启用该 MCP，或对话中没有引用该服务 | 按 Host 官方文档确认配置文件位置与启用方式；重启 Host；在对话中显式引用该服务后再试 |
| 工具调用返回 401 / 403 / 认证失败 | 凭证无效或权限不足（网络是通的） | 在目标系统重新生成凭证，用菜单 4 更新；Gerrit 可用菜单 4 的连通性测试复核 |
| 工具调用超时、无法解析主机名、连接被拒绝 | 网络不通、代理未配置，或 `baseUrl` 写错（内网系统须填内网地址） | 用浏览器访问 `baseUrl` 确认可达；检查代理；修正地址后重启 Host |
| Gerrit 工具调用提示 curl 相关错误 | PATH 中没有 `curl.exe` | 使用 Windows 10 及以上自带的 curl，或安装 curl 后重启 Host |
| 修改 `mcp.config.json` 后行为没有变化 | 服务进程仍在运行，读取的是启动时的旧值 | 重启 Host（或等待 Host 重新拉起该服务） |
| `var\tmp` 下残留 `gerrit-config-*.json` | 上次 Gerrit 服务进程被强制结束，启动器来不及删除临时文件 | 下次 Gerrit 启动时会自动清理属主进程已不存在的遗留文件；也可在确认没有 Gerrit 服务运行时手工删除 |
