## 2. 步骤 A：Host 启动后能看到 4 个 server

**操作**

1. 用文本编辑器打开导出的 Host 配置文件，复制 `mcpServers` 对象下的全部条目（从第一个 `{` 到最后一个 `}`，不含外层的 `"mcpServers":` 键名）。
2. 粘贴到 Host 的配置文件中，作为 `mcpServers` 对象的成员：
   - Cursor：`%USERPROFILE%\.cursor\mcp.json`
   - Claude Desktop：`%APPDATA%\Claude\claude_desktop_config.json`
   - 其他 Host：以其官方文档为准。文件已有其他 MCP 条目时合并到同一个 `mcpServers` 对象内，注意条目之间的逗号。
3. 完全退出 Host（含托盘与后台进程），重新启动。
4. 打开 Host 的 MCP / 工具列表。

**检查点**

## 3. 步骤 B：按需拉起

**说明**：传输模型（ADR-006）下，Host 在**首次调用某个服务的工具时**才拉起该服务的进程；部分 Host 会在启动时预先拉起全部条目。两种行为都可以接受，如实记录即可。

**操作 1：观察服务进程**（在仓库根目录的 PowerShell 中执行；可重复执行）

```powershell
# 只输出 PID 与进程名，不输出命令行（原因见下方说明）
$repo = (Resolve-Path '.').Path
$pattern = "Name='python.exe' OR Name='node.exe' OR Name='gerrit-mcp-server.exe' OR Name='github-mcp-server.exe'"
Get-CimInstance Win32_Process -Filter $pattern |
  Where-Object { $_.CommandLine -and $_.CommandLine.Contains($repo) -and $_.CommandLine -match 'mcp-(gerrit|github|jenkins|atlassian)\\' } |
  Select-Object ProcessId, ParentProcessId, Name, CreationDate | Format-Table -AutoSize
```

- 仓库内 venv 的 `python.exe` 是转发器，一个服务会显示多个进程（Gerrit 链路最多 5 个），属正常。
- **不要复制或截图完整命令行**：Gerrit 上游在发起 REST 请求的瞬间会以 `curl --user <用户名:HTTP 凭证>` 的参数启动 `curl.exe`，恰好抓取到并外传会造成凭证泄露（上游已知限制，见 `docs/services/服务接入说明.md` mcp-gerrit「已知限制」）。

**操作 2：在 Host 对话中各做一次只读调用**

| 服务（条目名） | 调用的工具 | 参数 | 期望结果 |
|---|---|---|---|
| mcp-gerrit | `query_changes` | `{"query": "is:open limit:1"}` | 返回变更列表（没有开放变更时为空列表，不算失败） |
| mcp-github | `get_me` | 无 | 返回当前令牌对应的账号 `login` |
| mcp-jenkins | `whoAmI` | 无 | 返回 Jenkins 用户名（匿名访问时为 `anonymous`） |
| mcp-atlassian | `jira_search` | `{"jql": "order by created DESC", "limit": 1}` | 返回最近 1 条工单（Jira 中无工单时为空，不算失败） |

**检查点**

| 检查点 | 期望 | 实际记录（由执行人填写） |
|---|---|---|
| B1 | 四个只读调用均成功返回，没有「工具不存在」「连接失败」类错误 |  |
| B2 | 调用前执行一次观察命令、调用后再执行一次：调用后能看到对应服务的进程 |  |
| B3 | 未被调用的服务：记录 Host 是否在启动时已预先拉起（是 / 否） |  |
| B4 | 各服务可用的工具数量与 `docs/operations/验收记录-M5至M8.md` 记录的一致（Gerrit 20 / GitHub 46 / Jenkins 14 / Atlassian 98）；数量不同时记录实际值 |  |

## 4. 步骤 C：关闭 Host 后无残留进程

**操作**

1. 完全退出 Host（含托盘与后台进程），在任务管理器中确认没有该 Host 的进程。
2. 等待 10 秒，执行 §3 的观察命令。
3. 执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\autostart.ps1`（登录预检，只读）。
4. 检查 Gerrit 临时配置目录 `var\tmp\`。

**检查点**

| 检查点 | 期望 | 实际记录（由执行人填写） |
|---|---|---|
| C1 | 观察命令无输出：仓库内已没有任何服务进程 |  |
| C2 | 登录预检的「提示」项中没有「遗留服务进程」「遗留临时配置」 |  |
| C3 | `var\tmp\` 下没有 `gerrit-config-<pid>.json`（Host 正常回收进程时启动器已删除） |  |

**关于总控的「遗留进程」检测**：mcpctl 菜单 2 / 菜单 3 与登录预检中的「遗留进程」判断**基于 PID 文件**，只用于发现早期版本 mcpctl 托管服务时留下的残留；ADR-006 之后 mcpctl 不再写 PID 文件，Host 拉起的进程**不在其检测范围内**。因此本步骤以观察命令的结果为准。

**C1 未通过时**（Host 退出后仍有进程）：

```powershell
# 仅结束本仓库内的服务进程（按进程树结束，先列出再结束；执行前确认列表中没有其他程序）
$repo = (Resolve-Path '.').Path
$pattern = "Name='python.exe' OR Name='node.exe' OR Name='gerrit-mcp-server.exe' OR Name='github-mcp-server.exe'"
$left = @(Get-CimInstance Win32_Process -Filter $pattern |
  Where-Object { $_.CommandLine -and $_.CommandLine.Contains($repo) -and $_.CommandLine -match 'mcp-(gerrit|github|jenkins|atlassian)\\' })
$left | Select-Object ProcessId, ParentProcessId, Name | Format-Table -AutoSize
$roots = @($left | Where-Object { $left.ProcessId -notcontains $_.ParentProcessId })
$roots | ForEach-Object { taskkill /PID $_.ProcessId /T /F }
```

清理后在 C1 的记录栏写明 Host 名称与版本，并在 `docs/operations/问题记录.md` 登记（这类 Host 每次退出后都需要清理一次）。若 C3 未通过（临时配置文件保留）：多半是 Host 强制结束了进程，启动器来不及删除；文件会在下次 Gerrit 启动时自动清理，属已知限制，在记录栏注明「保留」即可，不要手工打开该文件。

## 5. 步骤 D：日志无凭证泄露

**检查位置**

| 位置 | 内容 |
|---|---|
| 仓库 `logs\mcpctl-ops.log` | 总控操作日志（诊断、探活、导出、预检、自愈、清理） |
| 仓库 `logs\preflight-last.json` | 上次登录预检结果 |
| 各服务目录下的 `logs\`（如存在） | 早期版本留下的服务日志 |
| Host 的 MCP 日志（位置见 Host 文档） | 启动器的中文报错、Jenkins 启动器的「running for …」提示等 |

**操作**：在仓库根目录的 PowerShell 中执行下面的命令，对统一配置里的每个敏感字段（Gerrit 的 HTTP 凭证、GitHub 的个人访问令牌、Jenkins 的 API Token、Atlassian 的访问令牌）各执行一次第 1–4 行；凭证值通过隐藏输入提供，不会回显，也不会进入命令历史。

```powershell
$secure = Read-Host '粘贴一个凭证值（不回显）' -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
$secret = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr)
[Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr)

$files = @('logs\mcpctl-ops.log', 'logs\preflight-last.json') +
  @(Get-ChildItem -Path 'mcp-*\logs' -File -ErrorAction SilentlyContinue | ForEach-Object FullName)
$files | Where-Object { Test-Path -LiteralPath $_ } | ForEach-Object {
  '{0}: {1} 处命中' -f $_, @(Select-String -LiteralPath $_ -Pattern $secret -SimpleMatch).Count
}
Remove-Variable secret, secure, ptr
```

Host 的 MCP 日志不在仓库内：在其所在目录对日志文件执行同样的 `Select-String -LiteralPath <文件> -Pattern $secret -SimpleMatch`。

| 检查点 | 期望 | 实际记录（由执行人填写） |

| D1 | 四个敏感字段在全部检查文件中的命中数均为 0 |  |

| D3 | 操作日志中「导出Host配置」「登录预检」「环境自愈」等条目不含凭证值（由 D1 覆盖，单独确认一次） |  |

## 6. 步骤 E：配置改动后需重启 Host 才生效

**原因（写入使用约定）**：每个启动器在**进程启动时**读取一次 `env.MCP_SUITE_CONFIG` 指向的统一配置，并把本服务的配置段注入进程环境；此后对 `mcp.config.json` 的修改，对**已经在运行**的服务进程不生效，直到该进程被重新拉起——通常需要重启 Host。Host 配置文件本身（`command` / `args` / `env`）的修改同样需要重启 Host。

**操作**（以 Gerrit 为例，只做只读调用）

1. 保持 Host 运行，并已在 Host 中调用过 `mcp-gerrit` 的工具（进程已在运行）。
2. 在 mcpctl 菜单 4 配置向导中选择服务 A，把「Gerrit 实例地址」改为 `https://gerrit.invalid/`（一个不存在的地址），其余字段直接回车保留。
3. **不重启 Host**，在 Host 中再次调用 `query_changes`，记录结果。
4. 完全退出并重新启动 Host，再次调用 `query_changes`，记录结果。
5. 用菜单 4 把「Gerrit 实例地址」改回原值，重启 Host，再调用一次 `query_changes` 确认恢复。

**检查点**

| 检查点 | 期望 | 实际记录（由执行人填写） |
|---|---|---|
| E1 | 步骤 3：若 Gerrit 进程仍是之前那个（未被 Host 回收），调用结果与修改前相同（新值未生效）；若 Host 已回收并重新拉起进程，则调用失败（新值已生效）。两种情况都如实记录属于哪一种 |  |
| E2 | 步骤 4：重启 Host 后调用失败（启动器或上游报告无法连接 `gerrit.invalid`），证明新值在进程重新拉起后生效 |  |
| E3 | 步骤 5：改回原值并重启 Host 后调用恢复成功 |  |

## 8. 失败排查

单服务握手阶段的报错（统一配置不存在、字段未填写、上游服务缺失、二进制缺失等）及其处置见 `docs/operations/验收记录-M5至M8.md` §7，这里只列 Host 端到端阶段特有的现象。

| 现象 | 可能原因 | 处置 |
|---|---|---|
| Host 报配置文件解析错误 | 合并条目时多写 / 漏写逗号、括号不匹配、反斜杠未转义 | 用 JSON 校验工具检查 Host 配置文件；或用菜单 6 重新导出后整体替换 `mcpServers` 内容 |
| 条目显示连接失败或不可用 | `command` / `args` 不是本机绝对路径（仓库移动或换机器后未重新导出）；`env.MCP_SUITE_CONFIG` 指向的文件不存在 | 重新运行菜单 6 导出；用 `Test-Path -LiteralPath '<MCP_SUITE_CONFIG 的值>'` 确认文件存在 |
| Host 日志出现「统一配置文件不存在」「…未填写或仍是占位符」 | 统一配置未就绪 | 按报错里的「下一步」操作（菜单 4） |
| Host 日志出现「上游服务缺失：…」 | 依赖环境未初始化 | 运行菜单 5「初始化运行环境（Bootstrap）」，或执行菜单 7 预检给出的修复命令 |
| Host 日志出现「…已在统一配置中禁用」，或条目缺失 | 统一配置中该服务 `enabled=false` | 菜单 4 把「是否启用」改为「是」，重新导出并重启 Host |
| 只读调用返回认证失败（401 / 403） | 凭证过期、被重置或权限不足 | 在对应系统确认后，用菜单 4 更新凭证并重启 Host |
| 退出 Host 后仍有服务进程 | Host 未回收子进程 | 用 §4 的命令结束，并在记录栏写明 Host 名称与版本 |
| 修改统一配置后行为没有变化 | 服务进程仍是修改前拉起的旧进程 | 重启 Host（见步骤 E） |
| Gerrit 工具报 curl 相关错误 | PATH 中没有 `curl.exe` | 见 `docs/services/服务接入说明.md` mcp-gerrit「前置条件」 |
