> 传输模型（ADR-006）：四个服务一律由 Host（Cursor / Claude Desktop 等）按需以 stdio 拉起，进程生命周期由 Host 管理；**mcpctl 不托管服务进程**，仅提供诊断、探活与遗留进程清理。各服务在对应里程碑完成最小连通性验证后，回填“已验证版本”“实际工具集”“已知限制”。四个服务的配置集中在仓库根统一配置文件 `mcp.config.json`（已 gitignore），按 `services.<key>` 分段；字段、参考值与获取方式见 `docs/services/配置字段说明.md`（配置集中决策见 ADR-007）。

## 1. mcp-gerrit（Gerrit 代码评审）

| 项 | 内容 |
|---|---|
| 选型 | gerrit-mcp-server 1.0.8（PyPI，Apache-2.0）+ mcp 1.30.0（锁版见 `mcp-gerrit/requirements.txt`，原生支持 stdio 与 HTTP 两种模式，本仓库只用 stdio） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置段 | `services.gerrit`（统一配置 `mcp.config.json`；字段说明见 `docs/services/配置字段说明.md`） |
| 配置项 | 实例地址 `baseUrl`、实例名称 `instanceName`（可选）、用户名 `username`、HTTP 凭证 `httpPassword`（Gerrit 设置中的 HTTP Password，非登录密码）；`instances` 为多实例预留（当前版本不解析）；认证方式固定 http_basic |
| 规划能力 | 查询 change、获取 diff、添加评论、投票、增减 reviewer（实测 20 个工具，含 revert/abandon/set_topic 等） |
| 高危操作 | 投票、写评论、改 reviewer、abandon/revert 等写操作工具需二次确认 |
| Host 启动方式 | Host stdio 拉起服务 venv 的 `python.exe`，参数为仓库内 `mcp-gerrit/launcher.py`（见 `docs/host/Host接入配置.md`）。启动器读取统一配置的 `services.gerrit` 段（路径取环境变量 `MCP_SUITE_CONFIG`，未设置时回退仓库根 `mcp.config.json`），合成为上游要求的嵌套配置临时文件后以 `stdio` 模式拉起 `gerrit-mcp-server.exe`；总控仅诊断/探活/遗留清理，不托管进程 |
| 连通测试 | 已实装（只读）：统一配置就绪后调用 GET /a/accounts/self（HTTP Basic）返回账号身份；入口为 `scripts/mcpctl.ps1` 菜单 4 的连通性测试 |
| 前置条件 | ①Python 3.12+ 常规发行版（python.org；Microsoft Store 版在受限环境无法创建 venv）；②PATH 中有 curl.exe（Windows 10+ 自带）；③联网运行 `scripts/bootstrap.ps1` 初始化 venv 并按 `requirements.txt` 锁定安装 |
| 已验证版本 | gerrit-mcp-server 1.0.8 + mcp 1.30.0（经启动器从统一配置启动：stdio 握手正常，实测 20 个工具；真实实例 REST 只读连通与只读查询成功，2026-11-25） |
| 已知限制 | ①依赖 `mcp<2`（包声明的 mcp 无上限，装到 2.x 会因 FastMCP 改名而启动失败，requirements.txt 已锁定）；②运行依赖 PATH 中的 curl.exe（Windows 10+ 自带）；③需 Python 3.12+ 常规发行版（Microsoft Store 版受限环境无法创建 venv）；④启动器在运行期生成含凭证的临时配置文件（`var/tmp/gerrit-config-<pid>.json`，已 gitignore），服务退出时删除；若 Host 直接强杀服务进程，临时文件会保留到下次 Gerrit 启动时自动清理；⑤上游以 `curl --user <用户名:凭证>` 命令行方式调用 REST，凭证会短暂出现在本机进程命令行中（上游行为） |

## 2. mcp-github（GitHub / GitHub Enterprise）

| 项 | 内容 |
|---|---|
| 选型 | GitHub 官方 github-mcp-server v2.1.0（Go 单二进制本地部署；`mcp-github/setup-github-mcp.ps1` 锁定版本下载并做 SHA-256 校验） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置段 | `services.github`（统一配置 `mcp.config.json`；字段说明见 `docs/services/配置字段说明.md`） |
| 配置项 | 地址 `baseUrl`（github.com 或 GitHub Enterprise 的 API 地址）、个人访问令牌 `pat`、范围限定 `scope`（可选） |
| 规划能力 | 仓库与文件读取、Issue、PR、Workflow 触发等（按官方实现暴露） |
| Host 启动方式 | Host stdio 拉起 `node mcp-github/launcher.mjs`（launcher 读取统一配置的 `services.github` 段，注入 GITHUB_PERSONAL_ACCESS_TOKEN / GITHUB_HOST 后以 `stdio` 子命令启动 bin/github-mcp-server.exe；见 `docs/host/Host接入配置.md`）；总控仅诊断/探活/遗留清理，不托管进程 |
| 连通测试 | 待执行（专用连通性测试尚未提供；可先用菜单 1 的握手探活验证进程可拉起，真实连通需配置真实凭证后人工验证） |
| 约束 | 不使用官方远程托管 MCP 端点作为主路径 |
| 前置条件 | ①node 在 PATH 中；②首次须联网运行 `mcp-github/setup-github-mcp.ps1` 下载 v2.1.0 二进制并做 SHA-256 校验（`bin/` 不入库） |
| 已验证版本 | github-mcp-server v2.1.0（setup 脚本下载、SHA-256 校验通过、--version 正常；经启动器从统一配置启动：stdio 握手正常，实测 46 个工具；真实连通待配置真实凭证后执行） |
| 已知限制 | ①二进制不入库（bin/ 已被 .gitignore 排除），需先运行 setup 脚本获取；②GitHub.com 与 GHES 工具行为可能有差异，GHES 需配置 `baseUrl`；③launcher 对 `<占位符>` 视为未填并拒启；④首次获取二进制须联网（Bootstrap 对 binary 栈只检查、不下载）；⑤`scope` 当前不注入上游（官方服务器没有对应的范围限定参数），可见范围取决于 PAT 的权限 |


## 3. mcp-jenkins（Jenkins CI，零插件）

| 项 | 内容 |
|---|---|
| 选型 | jenkins-mcp-server 1.0.3（npm，REST API 远程调用；版本锁定见 `mcp-jenkins/package-lock.json`，`npm ci` 可复现安装） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置段 | `services.jenkins`（统一配置 `mcp.config.json`；字段说明见 `docs/services/配置字段说明.md`） |
| 配置项 | 实例地址 `baseUrl`、用户名 `username`、API Token `apiToken`、只读开关 `readOnly`（提示性）、多实例预留 `instances`（当前版本不解析） |
| 规划能力 | 查询 job/构建/日志/队列；触发构建等写操作默认二次确认 |
| 侵入性 | **不在 Jenkins 安装插件、不修改实例配置** |
| Host 启动方式 | Host stdio 拉起 `node mcp-jenkins/launcher.mjs`（launcher 读取统一配置的 `services.jenkins` 段，注入 JENKINS_URL / JENKINS_USERNAME / JENKINS_API_TOKEN 后动态 import 上游入口；见 `docs/host/Host接入配置.md`）；总控仅诊断/探活/遗留清理，不托管进程 |
| 前置条件 | ①node 与 npm 在 PATH 中；②联网运行 `scripts/bootstrap.ps1` 执行 `npm ci`（版本锁定见 `package-lock.json`） |
| 已验证版本 | jenkins-mcp-server 1.0.3（npm ci 安装验证通过；经启动器从统一配置启动：stdio 握手正常，实测 14 个工具；真实连通待凭证配置后执行） |
| 已知限制 | ①该实现无内建只读开关：统一配置的 `readOnly=true` 仅由启动器在 stderr 给出提示，不会拦截写操作工具，写操作由 Host 会话二次确认闸门管控；统一配置要求 `apiToken` 必填，不再支持留空匿名访问；②不同 Jenkins 版本 API 行为可能有差异；③专用连通性测试待提供，真实连通待凭证配置后人工验证；④launcher 以动态 import 加载上游包内部路径 `src/server/mcp-server.js`（非公开入口），上游升级若调整目录结构会导致启动失败，升级前须重新验证 |

## 5. 通用配置约定

- 统一配置文件为仓库根 `mcp.config.json`（已 gitignore），由 `mcp.config.sample.json` 复制或由配置向导生成，按 `services.gerrit` / `services.github` / `services.jenkins` / `services.atlassian` 分段；字段、参考值与获取方式以 `docs/services/配置字段说明.md` 为权威表，结构以 `mcp.config.schema.json` 为契约。
- 模板中敏感字段以占位符（`<...>`）表示，不得填真实值入库；启动器与就绪判定把占位符或空值视为未填写并拒绝启动。
- 录入统一走 `scripts/mcpctl.ps1` 菜单 4 的配置向导（逐字段展示中文说明、参考值与当前状态，敏感值不回显；支持从分服务旧配置导入）；各服务目录下不再新建配置文件。
- 新增或调整字段时，同步更新 `mcp.config.sample.json`、`mcp.config.schema.json`、`docs/services/配置字段说明.md` 与本文件对应服务表格。
