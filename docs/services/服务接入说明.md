> 传输模型（ADR-006）：四个服务一律由 Host（Cursor / Claude Desktop 等）按需以 stdio 拉起，进程生命周期由 Host 管理；**mcpctl 不托管服务进程**，仅提供诊断、探活与遗留进程清理。各服务在对应里程碑完成最小连通性验证后，回填“已验证版本”“实际工具集”“已知限制”。模板字段与本地配置一一对应；真实值只写入本地被 gitignore 的配置文件。

## 1. mcp-gerrit（Gerrit 代码评审）

| 项 | 内容 |
|---|---|
| 选型 | gerrit-mcp-server 1.0.8（PyPI，Apache-2.0）+ mcp 1.30.0（锁版见 `mcp-gerrit/requirements.txt`，原生支持 stdio 与 HTTP 两种模式，本仓库只用 stdio） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置模板 | `mcp-gerrit/gerrit_config.sample.json`（与包要求一致的嵌套结构：default_gerrit_base_url / gerrit_hosts[].authentication） |
| 配置项 | 实例地址、实例名称（可选）、用户名、HTTP 凭证（Gerrit 设置中的 HTTP Password）；认证方式固定 http_basic |
| 规划能力 | 查询 change、获取 diff、添加评论、投票、增减 reviewer（实测 20 个工具，含 revert/abandon/set_topic 等） |
| 高危操作 | 投票、写评论、改 reviewer、abandon/revert 等写操作工具需二次确认 |
| Host 启动方式 | Host stdio 拉起服务 venv 的 `gerrit-mcp-server.exe`，参数 `--config <本地配置路径> stdio`（见 `docs/host/Host接入配置.md`）；总控仅诊断/探活/遗留清理，不托管进程 |
| 连通测试 | 已实装（只读）：向导生成配置后调用 GET /a/accounts/self（HTTP Basic）返回账号身份 |
| 已验证版本 | gerrit-mcp-server 1.0.8 + mcp 1.30.0（stdio 握手正常，实测 20 个工具；REST 只读连通成功） |
| 已知限制 | ①依赖 `mcp<2`（包声明的 mcp 无上限，装到 2.x 会因 FastMCP 改名而启动失败，requirements.txt 已锁定）；②运行依赖 PATH 中的 curl.exe（Windows 10+ 自带）；③需 Python 3.12+ 常规发行版（Microsoft Store 版受限环境无法创建 venv） |

## 2. mcp-github（GitHub / GitHub Enterprise）

| 项 | 内容 |
|---|---|
| 选型 | GitHub 官方 github-mcp-server v2.1.0（Go 单二进制本地部署；`mcp-github/setup-github-mcp.ps1` 锁定版本下载并做 SHA-256 校验） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置模板 | `mcp-github/.env.template` |
| 配置项 | 实例地址（github.com / GHES）、PAT、可选组织/仓库范围 |
| 规划能力 | 仓库与文件读取、Issue、PR、Workflow 触发等（按官方实现暴露） |
| Host 启动方式 | Host stdio 拉起 `node mcp-github/launcher.mjs`（launcher 读 .env 并映射 GITHUB_PAT→GITHUB_PERSONAL_ACCESS_TOKEN 后启动 bin/github-mcp-server.exe；见 `docs/host/Host接入配置.md`）；总控仅诊断/探活/遗留清理，不托管进程 |
| 连通测试 | 待执行（配置真实凭证后运行向导连通测试；当前按决策仅占位） |
| 约束 | 不使用官方远程托管 MCP 端点作为主路径 |
| 已验证版本 | github-mcp-server v2.1.0（setup 脚本下载、SHA-256 校验通过、--version 正常；stdio 连通测试待配置真实凭证后执行） |
| 已知限制 | ①二进制不入库（bin/ 已被 .gitignore 排除），需先运行 setup 脚本获取；②GitHub.com 与 GHES 工具行为可能有差异，GHES 需配置 GITHUB_BASE_URL；③launcher 对 `<占位符>` 视为未填并拒启 |

## 3. mcp-jenkins（Jenkins CI，零插件）

| 项 | 内容 |
|---|---|
| 选型 | jenkins-mcp-server 1.0.3（npm，REST API 远程调用；版本锁定见 `mcp-jenkins/package-lock.json`，`npm ci` 可复现安装） |
| 运行形态 | 本地 stdio，由 Host 按需拉起 |
| 配置模板 | `mcp-jenkins/jenkins_config.sample.json` |
| 配置项 | 实例地址、用户名、API Token、可选多实例、只读模式开关 |
| 规划能力 | 查询 job/构建/日志/队列；触发构建等写操作默认二次确认 |
| 侵入性 | **不在 Jenkins 安装插件、不修改实例配置** |
| Host 启动方式 | Host stdio 拉起 `node mcp-jenkins/launcher.mjs`（launcher 读 jenkins_config.json 映射 JENKINS_URL/JENKINS_USERNAME/JENKINS_API_TOKEN 后动态 import 上游入口；见 `docs/host/Host接入配置.md`）；总控仅诊断/探活/遗留清理，不托管进程 |
| 已验证版本 | jenkins-mcp-server 1.0.3（npm ci 安装验证通过；stdio 连通测试待配置真实凭证后执行） |
| 已知限制 | ①该实现无内建只读开关，写操作工具由 Host 会话二次确认闸门管控（apiToken 留空则匿名只读访问）；②不同 Jenkins 版本 API 行为可能有差异；③连通测试待凭证配置后执行 |

## 5. 通用配置约定

- 模板中所有敏感字段以占位符（如 `<your-token>`）表示，不得填真实值入库。
- 本地配置文件命名与模板对应，去掉 `.sample`/`.template`，由 `.gitignore` 排除。
- 新增配置项时，同步更新本文件对应服务表格与配置模板。
