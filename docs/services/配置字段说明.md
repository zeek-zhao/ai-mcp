> 本文档是统一配置文件 `mcp.config.json` 的**权威字段表**：每个字段填什么、参考值是什么、去哪里获取。增减字段或改变字段语义时，必须同步更新 `mcp.config.sample.json`、`mcp.config.schema.json` 与本文档。

---

## 1. 文件位置

| 文件 | 用途 | 是否入库 |
|---|---|---|
| `<仓库根>/mcp.config.json` | 真实配置（含凭证） | 否：已被 `.gitignore` 忽略，永不入库 |
| `<仓库根>/mcp.config.sample.json` | 模板：参考值 + 每个字段的中文提示（`_hints`） | 是：随仓库分发 |
| `<仓库根>/mcp.config.schema.json` | JSON Schema：类型、必填、枚举，不含凭证 | 是 |

使用步骤（推荐走配置向导）：

1. 运行 `scripts/mcpctl.ps1`，进入菜单 4「配置向导」；统一配置文件不存在时向导会提示“将从模板生成”并创建 `mcp.config.json`。
2. 逐字段录入：每个字段先显示中文说明、参考值与当前状态（敏感字段只显示已设置 / 未设置），回车保留、输入 `-` 清空；已有分服务旧配置的可用「从旧配置导入」逐项迁移（旧文件不自动删除）。
3. 也可以手工编辑：复制 `mcp.config.sample.json` 为 `mcp.config.json`，按 `_hints` 的说明逐项填写，把 `<...>` 占位符换成真实值。
4. 用菜单 1 / 3 查看就绪状态；四个服务的配置都在这一个文件里，不再分服务维护。Host 配置通过 `env.MCP_SUITE_CONFIG` 指向该文件（见 `docs/host/Host接入配置.md`）。

## 2. 结构总览

```text
mcp.config.json
├─ configVersion    配置结构版本，当前固定为 1
├─ _comment         给人看的说明，程序读取时忽略
├─ services
│  ├─ gerrit        enabled / baseUrl / instanceName / username / httpPassword / instances
│  ├─ github        enabled / baseUrl / pat / scope
│  ├─ jenkins       enabled / baseUrl / username / apiToken / readOnly / instances
│  └─ atlassian     enabled / deployment / jiraBaseUrl / confluenceBaseUrl / email
│                   / personalAccessToken / projectScope / spaceScope
└─ _hints           字段路径 → 中文说明，给人看，程序读取时忽略
```

四个服务的段都必须存在。暂时不用的服务把 `enabled` 设为 `false`，不要删段。

## 3. 字段全表（参考值 / 提示 / 获取方式）

本表是权威表；`mcp.config.sample.json` 中的参考值与 `_hints` 均来自本表。

| 字段路径 | 必填 | 参考值 | 提示（要写进 sample 与向导） | 获取方式 |
|---|---|---|---|---|
| `services.gerrit.enabled` | 是 | `true` | 是否在菜单/导出中启用 Gerrit | — |
| `services.gerrit.baseUrl` | 是 | `https://gerrit.example.com` | 实例首页地址，**不要带末尾斜杠**，必须 http/https | 浏览器打开 Gerrit 首页复制 |
| `services.gerrit.instanceName` | 否 | `Gerrit` | 显示名称，仅本地标识用，可留空 | — |
| `services.gerrit.username` | 是 | `zhangsan` | **Gerrit 用户名**，不是邮箱、不是工号 | Gerrit 右上角头像 → Settings → Profile → Username |
| `services.gerrit.httpPassword` | 是 | `<HTTP 密码，非登录密码>` | 这是 HTTP 凭证，不是你的网页登录密码 | Settings → HTTP Credentials → Generate New Password |
| `services.gerrit.instances` | 否 | `[]` | 多实例场景才填，单实例留空数组 | — |
| `services.github.enabled` | 是 | `true` | 是否启用 GitHub | — |
| `services.github.baseUrl` | 是 | `https://github.com` | github.com 就填这个；GitHub Enterprise 填 `https://ghe.公司域名/api/v3` | — |
| `services.github.pat` | 是 | `<ghp_xxx 或 github_pat_xxx>` | 需 repo / issues / pull_requests 读权限；建议 fine-grained token | GitHub → Settings → Developer settings → Personal access tokens |
| `services.github.scope` | 否 | `""` | 限定 `owner/repo` 或组织名；留空=可见范围内全部 | — |
| `services.jenkins.enabled` | 是 | `true` | 是否启用 Jenkins | — |
| `services.jenkins.baseUrl` | 是 | `https://jenkins.example.com` | **不要带末尾斜杠**；若 Jenkins 挂在子路径（如 `/jenkins`）必须带上 | Jenkins 首页地址栏 |
| `services.jenkins.username` | 是 | `zhangsan` | Jenkins 登录用户名 | Jenkins → 右上角用户名 → Configure |
| `services.jenkins.apiToken` | 是 | `<API Token>` | 不是登录密码；可随时吊销 | Configure → API Token → Add new token |
| `services.jenkins.readOnly` | 否 | `true` | 仅提示性开关，上游无内建只读能力，**不会被强制拦截** | — |
| `services.jenkins.instances` | 否 | `[]` | 多实例地址列表，单实例留空 | — |
| `services.atlassian.enabled` | 是 | `true` | 是否启用 Atlassian（含 Jira + Confluence） | — |
| `services.atlassian.deployment` | 是 | `cloud` | Cloud 填 `cloud`；私有部署填 `server` | 看地址：`*.atlassian.net` = cloud |
| `services.atlassian.jiraBaseUrl` | 是 | `https://yourcompany.atlassian.net` | Cloud 不带 `/jira`；Server 填 Jira 根地址 | 浏览器地址栏 |
| `services.atlassian.confluenceBaseUrl` | 是 | `https://yourcompany.atlassian.net/wiki` | **Cloud 必须带 `/wiki`**，这是最常见填错点 | 浏览器地址栏 |
| `services.atlassian.email` | Cloud 必填 | `zhangsan@company.com` | Cloud 用登录邮箱；Server 用 PAT 时留空 | 你的 Atlassian 账号 |
| `services.atlassian.personalAccessToken` | 是 | `<API token 或 PAT>` | Cloud 填 API Token（与邮箱配对）；Server 填 Personal Access Token（Bearer） | Cloud：id.atlassian.com → Security → API tokens；Server：Profile → Personal Access Tokens |
| `services.atlassian.projectScope` | 否 | `[]` | 限制可访问的 Jira 项目 key，如 `["PROJ"]`；留空=全部 | — |
| `services.atlassian.spaceScope` | 否 | `[]` | 限制 Confluence space key，如 `["DEV"]`；留空=全部 | — |

## 4. 填写规则

### 4.1 占位符与就绪判定

- 占位符统一写作 `<...>`。尖括号内是填写说明，不是真实值。模板里敏感字段的参考值就是占位符，例如 `<API Token>`。
- 就绪判定由 mcpctl 执行，规则：服务已启用（`enabled` 为 `true`），且第 3 节「必填」列为「是」的字段都**非空、且不是 `<...>` 占位符**，才算就绪。`services.atlassian.email` 只在 `deployment` 为 `cloud` 时参与判定。
- `enabled` 为 `false` 的服务不参与就绪判定，其必填项允许留空。
- 模板中的非敏感参考值（如 `https://gerrit.example.com`、`zhangsan`）只是示例，使用前必须改成自己的值。

### 4.2 Schema 校验范围

`mcp.config.schema.json` 与就绪判定分工如下，二者不重复。

| 由 Schema 负责 | 由 mcpctl 就绪判定负责 |
|---|---|
| 顶层键、四个服务段是否齐全；有无未知键（未知键一律拒绝） | 必填项是否非空、是否仍是 `<...>` 占位符 |
| 字段类型（字符串 / 布尔 / 数组）与 `deployment` 枚举（`cloud`、`server`） | 地址能否连通、凭证是否有效 |
| `configVersion` 必须为 `1` | 服务是否已启用 |
| 地址字段必须是 `http://` 或 `https://` 开头，或为空串 | — |
| Cloud 部署且启用时，`email` 必须有值 | — |

补充约定：

- 必填**键**必须出现，但值允许是空串，以便未启用的服务留空；是否为空交给就绪判定。
- 地址末尾斜杠按第 3 节提示不要带。Schema 不做拦截；启动器读取时应自行去掉末尾斜杠，不依赖 Schema。
- 手工改完配置后，若 mcpctl 报「格式错误」，按提示修正字段名、类型或取值；这类错误与凭证是否正确无关。

### 4.3 `_comment` 与 `_hints`

两者都是给人看的，程序读取时**必须忽略**，缺失也不影响读取。`_hints` 的键是完整字段路径，值是中文说明。

### 4.4 `services.atlassian.deployment`

| 取值 | 适用 | 凭证字段 |
|---|---|---|
| `cloud` | 公有云，地址形如 `*.atlassian.net` | `email`（登录邮箱）必填 + `personalAccessToken` 填 API Token |
| `server` | Server / Data Center 私有部署 | `personalAccessToken` 填 Personal Access Token（Bearer）；`email` 可留空 |

### 4.5 `instances`

多实例场景的预留字段。`configVersion` 为 `1` 时不约定元素结构，程序不解析该字段，只使用 `baseUrl` 等单实例字段。单实例留空数组 `[]`。多实例的定义在升级 `configVersion` 时补充。

### 4.6 `services.jenkins.readOnly`

仅提示性开关。上游 jenkins-mcp-server 没有内建的只读能力，设为 `true` **不会被强制拦截**写操作；高危操作的确认闸由 Host 侧交互流程保证，见 `docs/services/服务接入说明.md`。

### 4.7 `configVersion`

当前为 `1`。增减字段或改变字段语义时升级版本，并同步更新 `mcp.config.sample.json`、`mcp.config.schema.json` 与本文档。
