> `scripts/tests/` 下的自检脚本用**固定的退出码**回答「各服务现在能不能用、升级后工具有没有变」。本文档说明文件构成、四态退出码、五种运行模式（直连 / 结构 / 网关 / 快照 / 对比）、常用命令，以及新增或升级服务时如何维护用例与工具快照。

---

## 1. 文件构成

| 文件 | 作用 |
|---|---|
| `scripts/tests/run-tests.bat` | 总入口：先预检，再按 `cases/services.json` 依次调用每个 `test-<配置段>.bat`（`--service`、`--only` 可缩小范围），汇总为一个退出码 |
| `scripts/tests/test-gerrit.bat`、`test-github.bat`、`test-jenkins.bat`、`test-atlassian.bat` | 单服务入口，参数原样传给核心脚本 |
| `scripts/tests/preflight.bat` | 只做预检（依赖、统一配置、启动命令、网关可达性），不拉起服务 |
| `scripts/tests/lib/mcp-stdio-test.mjs` | 核心实现（Node 18+，只用内置模块，不依赖仓库内的 `node_modules`） |
| `scripts/tests/lib/list-case-keys.mjs` | 给 `run-tests.bat` 列出要执行的配置段：读用例文件，按 `--service`、`--only` 筛选 |
| `scripts/tests/cases/services.json` | 用例：每个服务一条，含期望工具数与一次只读调用 |
| `scripts/tests/tools-snapshot/<服务Id>.json` | 工具快照：`tools/list` 的工具名、说明摘要哈希、必填字段与参数名列表（入库；不含凭证与实例信息） |
| `scripts/tests/lib/check-pr-tool-diff.mjs` | CI 使用：比较 PR 与基线的期望工具数，变化超过 ±20% 时要求 PR 描述附「工具快照差异」摘要 |

只依赖 PATH 上的 `node`；不需要 PowerShell，也不需要仓库内的依赖目录即可完成结构校验。

## 2. 退出码（四态）

| 退出码 | 名称 | 含义 | 典型原因 |
|---|---|---|---|
| `0` | PASS | 所选服务全部通过；`SKIP` 不计失败 | 握手成功、工具数与期望一致、只读调用成功 |
| `1` | FAIL | 至少一项断言失败 | 结构校验不一致（用例与注册表 / 模板 / 网关样例 / 启动器文件对不上）、工具数不符、只读调用返回错误 |
| `2` | BLOCKED | 环境或前置不满足，测试无法执行 | 找不到 `node`、依赖未安装、统一配置缺失或未就绪、启动器无法拉起、网关不可达 |
| `3` | USAGE | 参数错误 | 未知参数、`--via` 取值不合法、缺少取值 |

规则：

- 多个服务同时运行时取最严重的结果：`FAIL` > `BLOCKED` > `PASS`；参数错误发现即返回 `3`。
- `run-tests.bat` 的汇总优先级为 `1` > `2` > `3` > `0`，末行形如 `[run-tests] overall exit code 0 = PASS`。
- `SKIP` 只出现在有明确理由时（服务在统一配置中被禁用；结构模式下启动器按预期拒绝模板配置；`--only` 未选中）。

## 3. 运行模式

| 模式 | 触发方式 | 做什么 | 需要凭证 | 需要依赖环境 |
|---|---|---|---|---|
| 直连 | `run-tests.bat`（默认） | 按注册表的 `StartCommand` 直接拉起启动器，握手 → `tools/list` → 一次只读 `tools/call` | 是 | 是 |
| 结构 | `run-tests.bat --structural` | 以模板 `mcp.config.sample.json` 为配置拉起启动器，预期各服务都**拒绝模板值**并退出，记 `SKIP`；无需凭证，用于 CI | 否 | 否（未安装时自动跳过） |
| 网关 | `run-tests.bat --via gateway` | 经 Magpie 网关（streamable-http）调用，工具名按 `<服务名>__<工具名>` 匹配，例如 `Gerrit__query_changes` | 是（由网关侧的启动器读取） | 是（网关侧） |
| 快照 | `run-tests.bat --snapshot` | 握手后把 `tools/list` 写入 `scripts/tests/tools-snapshot/<服务Id>.json`（覆盖）；工具数与 `expectedTools` 不符时仍写入，但记 `FAIL`，提示先更新用例 | 是 | 是 |
| 对比 | `run-tests.bat --diff` | 握手后把当前 `tools/list` 与快照比较，输出「新增 / 删除 / 签名变化」三类清单；有差异退出码 `1`，无差异 `0`；不做只读调用 | 是 | 是 |

`--snapshot` 与 `--diff` 互斥，都不能与 `--structural`、`--via gateway`、`--preflight` 同用（否则返回 `3`）；两者与 `--structural` 一样不触发登录预检。

各模式都先做**结构校验**（不依赖凭证与依赖环境）：用例 `id` 不重复；注册表中每个服务都有对应用例；`configKey`、`gatewayName` 与注册表、`scripts/lib/gateway-routes.ps1` 一致；`gatewayName` 出现在 `gateway.routes.sample.json`；`expectedTools` 为正整数；`StartCommand` 至少两项且启动器文件存在；模板含对应配置段。任何一项不满足即返回 `1`。

### 3.1 工具快照与对比

- 快照文件每个工具只记录四项：`name`（工具名）、`descriptionHash`（说明文本的 SHA-256 前 16 位，不存原文）、`required`（`inputSchema.required` 排序去重）、`properties`（`inputSchema.properties` 的参数名排序去重）。文件顶层另有 `_comment`、`service`、`capturedAt`（日期）与 `toolCount`。不写入说明原文、参数结构、凭证或任何实例信息。
- 一个工具的**签名** = 必填字段 + 参数名 + 说明哈希。对比时三者任一不同即记为「签名变化」，并指出是哪一项变了，例如 `签名变化：query_changes（必填字段 快照 [] → 当前 [query]（新增 query）；参数 快照 3 个 → 当前 4 个（新增 options））`。
- 除 `--snapshot` 外，结构校验同时校验快照：每个用例都有快照文件；没有对应用例的快照文件会报错；`toolCount` 与工具条数一致；工具名不重复；快照工具数与 `expectedTools` 一致（不一致时提示先 `--diff` 评估差异、再 `--snapshot` 更新快照）。因此 CI 上只要快照、用例与注册表三者对不上就会失败。
- 快照的更新流程（先对比、再评估、后更新）见 `docs/planning/升级MCP服务工作流.md`；新增服务时用 `--snapshot` 生成第一份快照，见 `docs/planning/新增MCP服务工作流.md`。

## 4. 常用命令

在仓库根目录执行：

```bat
scripts\tests\run-tests.bat                        :: 直连：各服务握手 + 工具数 + 只读调用
scripts\tests\run-tests.bat --structural           :: 结构：无需凭证，CI 使用
scripts\tests\run-tests.bat --via gateway          :: 网关：经 Magpie 调用
scripts\tests\test-gerrit.bat                      :: 单服务
scripts\tests\run-tests.bat --only gerrit,github   :: 只跑选中的服务（服务 Id、配置段名或 mcp-<配置段名> 均可）
scripts\tests\run-tests.bat --expect-tools 21      :: 临时覆盖期望工具数（验证「工具数不符 → 退出码 1」）
scripts\tests\run-tests.bat --snapshot             :: 快照：把当前 tools/list 写入 scripts/tests/tools-snapshot/
scripts\tests\run-tests.bat --service gerrit --diff :: 对比：当前工具与快照的差异（有差异退出码 1）
scripts\tests\preflight.bat                        :: 只预检
```

路径规则与启动器一致：统一配置按 `MCP_SUITE_CONFIG` > `MCP_SUITE_ROOT\mcp.config.json` > `<仓库根>\mcp.config.json` 定位；仓库根优先取有效的 `MCP_SUITE_ROOT`，否则按脚本位置推断（见 `docs/host/Host接入配置.md` 第 0 节）。

网关模式默认连接本机正在运行的 Magpie（回环地址上的 hub 端点，agent 名 `dsh`，与 Magpie 自带的默认配置一致）；其他 agent 用 `--gateway-agent <名称>`，端口或主机不同用 `--gateway-url <完整地址>` 指定。

## 5. 用例格式

`scripts/tests/cases/services.json`：

```json
{
  "id": "mcp-gerrit",
  "configKey": "gerrit",
  "gatewayName": "Gerrit",
  "expectedTools": 20,
  "readOnlyCall": { "tool": "query_changes", "arguments": { "query": "is:open limit:1" } }
}
```

| 字段 | 说明 |
|---|---|
| `id` | 注册表中的服务 Id（`scripts/mcpctl.config.ps1`） |
| `configKey` | 统一配置中的配置段名 |
| `gatewayName` | Magpie 路由中的服务名（`scripts/lib/gateway-routes.ps1` 的 `McpGatewayNames`） |
| `expectedTools` | `tools/list` 的期望数量；须与工具快照的 `toolCount` 一致。上游升级导致变化时先 `--diff` 评估差异，再更新该值并用 `--snapshot` 更新快照，在 PR 中说明差异（变化超过 ±20% 时 PR 描述须附「工具快照差异」摘要） |
| `readOnlyCall` | 一次只读调用；`arguments` 不得包含凭证或实例地址 |

新增或修改用例后先跑 `scripts\tests\run-tests.bat --structural`：结构校验会指出缺哪一条、哪个字段对不上。

## 6. CI 接入

| 位置 | 内容 | 是否必需检查 |
|---|---|---|
| `checks` 作业（ubuntu）步骤「自检脚本结构模式（Node 直跑）」 | `node scripts/tests/lib/mcp-stdio-test.mjs --structural` | 是（`checks` 为必需检查） |
| `structural-tests` 作业（windows-latest） | `scripts\tests\run-tests.bat --structural` | 否（尚未加入分支保护的必需检查） |
| `checks` 作业步骤「PR 工具数变化校验」（仅 `pull_request` 事件） | `node scripts/tests/lib/check-pr-tool-diff.mjs --base <基线提交> --body-file <PR 描述>` | 是（`checks` 为必需检查） |

Windows 作业上没有仓库内的依赖目录：结构模式下两个 Python 服务会回退到 PATH 上的 Python（须实测可运行，Windows 商店占位程序会被排除），各服务因模板值被启动器拒绝而全部 `SKIP`，整体返回 `0`。

「PR 工具数变化校验」比较 PR 与基线提交中 `cases/services.json` 的 `expectedTools`（基线没有的服务视为新增服务，不要求摘要）：

- 变化幅度超过 ±20%（恰等于 20% 不算超过）时，PR 描述必须包含「工具快照差异」字样，否则步骤失败，并提示运行 `scripts\tests\run-tests.bat --diff` 后把清单粘贴进描述。
- 未超过阈值或工具数未变化时直接通过，并在日志中给出对比结果。
- 读不到基线提交时步骤失败（校验未完成不等于通过）。

## 7. 安全约定

- 只打印工具名、条数、耗时与成败；不打印统一配置的任何取值。
- 错误文本中的 http(s) 地址替换为 `<地址>`，32 位以上的随机串替换为 `<已隐藏>`。
- 只读调用来自用例文件，用例文件不得包含凭证或实例地址；直连模式在统一配置未就绪时直接返回 `2`，不会带着模板值去连接任何实例。
