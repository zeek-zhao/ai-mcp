> `scripts/tests/` 下的自检脚本用**固定的退出码**回答「四个服务现在能不能用」。本文档说明文件构成、四态退出码、三种模式、常用命令，以及新增服务时如何补用例。

---

## 1. 文件构成

| 文件 | 作用 |
|---|---|
| `scripts/tests/run-tests.bat` | 总入口：先预检，再依次跑四个服务的用例，汇总为一个退出码 |
| `scripts/tests/test-gerrit.bat`、`test-github.bat`、`test-jenkins.bat`、`test-atlassian.bat` | 单服务入口，参数原样传给核心脚本 |
| `scripts/tests/preflight.bat` | 只做预检（依赖、统一配置、启动命令、网关可达性），不拉起服务 |
| `scripts/tests/lib/mcp-stdio-test.mjs` | 核心实现（Node 18+，只用内置模块，不依赖仓库内的 `node_modules`） |
| `scripts/tests/cases/services.json` | 用例：每个服务一条，含期望工具数与一次只读调用 |

只依赖 PATH 上的 `node`；不需要 PowerShell，也不需要仓库内的依赖目录即可完成结构校验。

---

## 2. 退出码（四态）

| 退出码 | 名称 | 含义 | 典型原因 |
|---|---|---|---|
| `0` | PASS | 所选服务全部通过；`SKIP` 不计失败 | 握手成功、工具数与期望一致、只读调用成功 |
| `1` | FAIL | 至少一项断言失败 | 结构校验不一致（用例与注册表 / 模板 / 网关样例 / 启动器文件对不上）、工具数不符、只读调用返回错误 |
| `2` | BLOCKED | 环境或前置不满足，测试无法执行 | 找不到 `node`、依赖未安装、统一配置缺失或未就绪、启动器无法拉起、网关不可达 |
| `3` | USAGE | 参数错误 | 未知参数、`--via` 取值不合法、缺少取值 |

规则：

- 多个服务同时运行时取最严重的结果：`FAIL` > `BLOCKED` > `PASS`；参数错误发现即返回 `3`。
- `run-tests.bat` 的汇总优先级为 `1` > `2` > `3` > `0`，末行形如 `[run-tests] overall exit code 0 = PASS`。
- `SKIP` 只出现在有明确理由时（服务在统一配置中被禁用；结构模式下启动器按预期拒绝模板配置；`--only` 未选中）。

## 3. 三种模式

| 模式 | 触发方式 | 做什么 | 需要凭证 | 需要依赖环境 |
|---|---|---|---|---|
| 直连 | `run-tests.bat`（默认） | 按注册表的 `StartCommand` 直接拉起启动器，握手 → `tools/list` → 一次只读 `tools/call` | 是 | 是 |
| 结构 | `run-tests.bat --structural` | 以模板 `mcp.config.sample.json` 为配置拉起启动器，预期四个服务都**拒绝模板值**并退出，记 `SKIP`；无需凭证，用于 CI | 否 | 否（未安装时自动跳过） |
| 网关 | `run-tests.bat --via gateway` | 经 Magpie 网关（streamable-http）调用，工具名按 `<服务名>__<工具名>` 匹配，例如 `Gerrit__query_changes` | 是（由网关侧的启动器读取） | 是（网关侧） |

三种模式都先做**结构校验**（不依赖凭证与依赖环境）：用例 `id` 不重复；注册表中每个服务都有对应用例；`configKey`、`gatewayName` 与注册表、`scripts/lib/gateway-routes.ps1` 一致；`gatewayName` 出现在 `gateway.routes.sample.json`；`expectedTools` 为正整数；`StartCommand` 至少两项且启动器文件存在；模板含对应配置段。任何一项不满足即返回 `1`。

## 4. 常用命令

在仓库根目录执行：

```bat
scripts\tests\run-tests.bat                        :: 直连：四服务握手 + 工具数 + 只读调用
scripts\tests\run-tests.bat --structural           :: 结构：无需凭证，CI 使用
scripts\tests\run-tests.bat --via gateway          :: 网关：经 Magpie 调用
scripts\tests\test-gerrit.bat                      :: 单服务
scripts\tests\run-tests.bat --only gerrit,github   :: 只跑选中的服务（服务 Id、配置段名或 mcp-<配置段名> 均可）
scripts\tests\run-tests.bat --expect-tools 21      :: 临时覆盖期望工具数（验证「工具数不符 → 退出码 1」）
scripts\tests\preflight.bat                        :: 只预检
```

路径规则与启动器一致：统一配置按 `MCP_SUITE_CONFIG` > `MCP_SUITE_ROOT\mcp.config.json` > `<仓库根>\mcp.config.json` 定位；仓库根优先取有效的 `MCP_SUITE_ROOT`，否则按脚本位置推断（见 `docs/host/Host接入配置.md` 第 0 节）。

网关模式默认连接本机正在运行的 Magpie（回环地址上的 hub 端点，agent 名 `dsh`，与 Magpie 自带的默认配置一致）；其他 agent 用 `--gateway-agent <名称>`，端口或主机不同用 `--gateway-url <完整地址>` 指定。

## 5. 用例格式

`scripts/tests/cases/services.json`：

```json
{
  "id": "mcp-gerrit",
  "configKey": "gerrit",
  "gatewayName": "Gerrit",
  "expectedTools": 20,
  "readOnlyCall": { "tool": "query_changes", "arguments": { "query": "is:open limit:1" } }
}
```

| 字段 | 说明 |
|---|---|
| `id` | 注册表中的服务 Id（`scripts/mcpctl.config.ps1`） |
| `configKey` | 统一配置中的配置段名 |
| `gatewayName` | Magpie 路由中的服务名（`scripts/lib/gateway-routes.ps1` 的 `McpGatewayNames`） |
| `expectedTools` | `tools/list` 的期望数量；上游升级导致变化时先更新该值，并在 PR 中说明差异 |
| `readOnlyCall` | 一次只读调用；`arguments` 不得包含凭证或实例地址 |

新增或修改用例后先跑 `scripts\tests\run-tests.bat --structural`：结构校验会指出缺哪一条、哪个字段对不上。

## 6. CI 接入

| 位置 | 内容 | 是否必需检查 |
|---|---|---|
| `checks` 作业（ubuntu）步骤「自检脚本结构模式（Node 直跑）」 | `node scripts/tests/lib/mcp-stdio-test.mjs --structural` | 是（`checks` 为必需检查） |
| `structural-tests` 作业（windows-latest） | `scripts\tests\run-tests.bat --structural` | 否（尚未加入分支保护的必需检查） |

Windows 作业上没有仓库内的依赖目录：结构模式下两个 Python 服务会回退到 PATH 上的 Python（须实测可运行，Windows 商店占位程序会被排除），四个服务因模板值被启动器拒绝而全部 `SKIP`，整体返回 `0`。

---

## 7. 安全约定

- 只打印工具名、条数、耗时与成败；不打印统一配置的任何取值。
- 错误文本中的 http(s) 地址替换为 `<地址>`，32 位以上的随机串替换为 `<已隐藏>`。
- 只读调用来自用例文件，用例文件不得包含凭证或实例地址；直连模式在统一配置未就绪时直接返回 `2`，不会带着模板值去连接任何实例。
