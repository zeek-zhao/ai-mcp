## 1. 项目背景与目标

### 1.1 背景
在本地 Windows 机器上，为大模型 Host（如 Cursor、Claude Desktop 等）提供一组由 Host（Cursor、Claude Desktop 等）按需 stdio 拉起的 MCP（Model Context Protocol）服务，统一对接企业内部与代码协作系统。

### 1.2 核心目标
1. 在一个 GitHub 仓库内收纳全部 MCP 服务的代码、配置模板、启动/停止/配置脚本与依赖锁定文件。
2. 每个外部系统对应一个**独立 MCP Server 进程**，互不影响，可单独调试、单独启停。
3. 提供一个**全中文分步提示式总控脚本**，按菜单引导用户完成服务诊断、遗留进程清理、状态查看、Host 配置导出、配置维护与依赖初始化（服务进程由 Host 按需拉起，总控不托管，见 ADR-006）。
4. 全部依赖在仓库内隔离管理，不污染 Windows 全局环境；所有凭证仅存本地，不提交 Git。
5. 项目全过程通过 GitHub 仓库、Issue、PR、里程碑（Milestone）进行管理。

### 1.3 范围（In Scope）
| 编号 | 服务代号 | 对接系统 | 说明 |
|---|---|---|---|
| A | `mcp-gerrit` | Gerrit（代码评审） | 查询 change、diff、评论、投票、reviewer 等 |
| B | `mcp-github` | GitHub / GitHub Enterprise | 仓库、文件、Issue、PR、Workflow 等 |
| C | `mcp-jenkins` | Jenkins（CI） | 查 job、触发构建、拉日志、队列等；**不向 Jenkins 安装任何插件** |
| D | `mcp-atlassian` | Atlassian（Jira + Confluence 一体化） | 工单与页面的搜索、读写；统一归在 Atlassian 命名下 |

### 1.4 不在本期范围（Out of Scope）
- 远程公网暴露 MCP 服务、多用户鉴权网关（列为后续演进）。
- 修改 Jenkins 实例、在 Jenkins 侧安装 MCP 插件。
- 接入 GitLab、Bitbucket 等其他系统（预留扩展位，不在本期实现）。
- 云端 Atlassian 官方远程 MCP 桥接（仅作为备选记录，不纳入主路径）。

## 2. 硬性约束（实现时必须遵守）

1. **平台**：脚本与运行环境面向 Windows；脚本以 PowerShell 为主。
2. **架构**：方案 A —— 多个独立 MCP Server，禁止合并成单聚合大单体。
3. **零侵入 Jenkins**：仅通过 Jenkins REST API + 用户 API Token 远程调用，不在 Jenkins 上装插件、改配置。
4. **本地优先**：MCP 进程在本地 Windows 机器运行；优先 `stdio` 按需拉起；不依赖外部托管 MCP 端点。
5. **依赖仓库内隔离**：每个子服务使用目录内独立虚拟环境/依赖目录，依赖版本用锁定文件固定；不使用系统全局 Python/Node 环境作为运行前提。
6. **凭证安全**：真实地址、Token、密码、私钥一律不入 Git；仓库只保留统一配置模板 `mcp.config.sample.json` 与结构契约 `mcp.config.schema.json`（ADR-007）；敏感输入在交互时隐藏不回显。
7. **按需拉起**：MCP 服务一律由 Host 按需 stdio 拉起；总控不后台托管服务进程，仅提供诊断、探活与遗留进程清理。
8. **进程治理**：总控不做服务停止托管；发现疑似遗留进程时，先诊断展示，经用户二次确认后以 taskkill 强杀进程树并清理 PID 残留。
9. **登录预检**：登录自动常驻已取消（ADR-005/ADR-006）；代之以登录预检与环境自愈（M9），默认不拉起任何 MCP 进程。
10. **全中文交互**：菜单、提示、状态文案、错误提示均使用中文。

## 3. 架构决策记录

> 详细决策与理由见 `docs/architecture/架构与决策记录.md`。

### 3.1 为什么选“多独立 MCP Server”
| 决策点 | 选择 | 理由 |
|---|---|---|
| 进程模型 | 一服务一进程，由 Host 按需 stdio 拉起 | 隔离故障、独立鉴权；stdio 通道由 Host 与服务一对一持有，符合 MCP 原生设计（ADR-006） |
| 服务接入方式 | 独立 MCP Server 调用外部 REST API | 对被对接系统零改造；Jenkins 约束可满足 |
| 总控形态 | PowerShell 交互脚本（菜单式，治理工具定位） | Windows 自带、无需额外全局依赖；负责诊断/探活/遗留清理/Host 配置导出，不托管服务进程 |
| 配置形态 | 仓库根单一统一配置文件 `mcp.config.json` + 仓库内模板与 Schema（ADR-007） | 凭证不入库；一份配置供四个服务与总控共用；模板可被多人复用 |
| 常驻方式 | 已取消（ADR-005/006）；改为登录预检与环境自愈（M9） | 登录常驻与 Host 生命周期冲突；预检不拉起进程 |

### 3.2 服务选型结论
| 服务 | 选型 | 运行形态 | 备注 |
|---|---|---|---|
| Gerrit | 社区/官方 gerrit-mcp-server（Python） | 本地 stdio | 适配 Gerrit 评审模型；用仓库内 venv 管理 |
| GitHub | GitHub 官方 github-mcp-server（本地部署模式） | 本地 stdio / 本地进程 | 锁定版本放入仓库；使用 PAT |
| Jenkins | 社区独立 jenkins-mcp（外部调用 REST API） | 本地 stdio | 零插件；支持多实例；高危操作需确认 |
| Atlassian | 社区本地一体化 Atlassian MCP（Jira + Confluence DC/Server） | 本地 stdio | 内网可控；需验证 Data Center 兼容性 |

> 选型在实现前需在对应里程碑中做一次最小连通性验证；若所选社区项目不满足约束，需先在问题记录/Issue 中登记并替换为等价方案，再进入实现。

### 4.1 路径与命名约定
- 所有脚本使用仓库相对路径定位子服务；不写死绝对路径。
- 子服务目录名与服务代号保持一致。
- 运行时产物（`logs/`、`run.pid`、`var/`、虚拟环境、`node_modules/`）与本地统一配置 `mcp.config.json` 全部进入 `.gitignore`。

## 5. GitHub 协作流程规范

> 分支、提交、Issue、PR、CI、主干保护的完整规则见 `ai/交付与PR规范.md` 与 `.github/` 模板。

### 5.1 分支模型（GitHub Flow）
- `main`：受保护主干，始终保持可运行、可说明文档完整的状态。
- 功能分支命名：`feat/<服务或模块>-<简述>`、`fix/<简述>`、`chore/<简述>`、`docs/<简述>`。
- 每个里程碑对应一个 GitHub Milestone；相关 Issue 与 PR 挂到对应 Milestone。

### 5.2 Commit 规范（Conventional Commits）
格式：`<type>(<scope>): <摘要>`；`feat/fix/chore/docs/refactor/test`；摘要默认中文。

### 5.3 Issue 与 PR
- 每个里程碑先拆 Issue，类型对应模板；标签含里程碑、服务、类型三类。
- PR 必须填写关联 Issue、变更类型、变更内容、自测清单、风险点；合并前通过 CI。
- 合并方式优先 Squash Merge。

### 5.4 CI 校验项
| 校验项 | 说明 |
|---|---|
| PowerShell 语法解析 | 对 `scripts/**/*.ps1` 做静态解析 |
| 配置契约校验 | 检查统一配置模板可解析、字段提示齐全、Schema 必填集合一致；真实配置 `mcp.config.json` 与依赖产物未被跟踪 |
| 密钥扫描 | 扫描疑似 Token/密码 |
| 文档一致性 | 检查 README、目录结构与服务注册表一致 |

### 5.5 版本与发布
- 每个里程碑完成并合并后归档 Milestone；必要时打语义化 Tag。
- Release Notes 记录：新增服务、脚本能力、配置变更、已知限制。

## 7. 安全与合规要求

> 完整要求见 `docs/security/安全与凭证管理.md`。

1. **凭证管理**：仓库只存统一配置模板 `mcp.config.sample.json` 与 Schema；真实配置 `mcp.config.json` 加入 `.gitignore`；敏感输入隐藏；日志不输出明文凭证。
2. **权限最小化**：各服务使用专用账号/Token；优先只读，写操作按需开放并二次确认。
3. **密钥扫描**：CI 启用密钥扫描；发现疑似凭证即阻断合并。
4. **网络边界**：主路径仅访问内网/本地可达实例；不将凭证或内部地址外泄到第三方服务。
5. **审计**：记录启停、配置变更、连通测试结果；审计日志不含敏感值。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 社区 MCP 项目维护停滞或兼容性不足 | 服务无法接入 | 里程碑内先做最小验证；不满足则在问题记录中替换等价实现并记录决策 |
| Jenkins / Gerrit / Atlassian 版本 API 差异 | 探活或工具调用失败 | 文档记录已验证版本范围；配置中预留 API 路径/版本参数 |
| Windows 环境编码、路径、执行策略问题 | 脚本无法运行 | Bootstrap 阶段检测 PowerShell 执行策略；文档注明所需策略；路径全部相对仓库定位 |
| 误提交凭证 | 安全泄露 | `.gitignore` + CI 密钥扫描 + PR 检查项三重保障 |
| 单服务探活失败影响整体 | 诊断/探活中断 | 探活按单服务隔离执行，失败汇总不阻断其余服务 |
| 统一配置单文件聚合全部凭证 | 文件泄露影响全部服务 | 原子写入、仅本机可读、禁止网盘/邮件同步、`enabled=false` 停用闲置服务（ADR-007） |
