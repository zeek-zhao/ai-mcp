## 1. 凭证管理

1. 仓库只保留 `*.sample` / `*.template` 模板；真实配置加入 `.gitignore`，不进入版本库。
2. 配置向导中 Token、密码类输入隐藏不回显；写入本地配置后不在控制台、日志、审计记录中复述明文。
3. 代码注释、Commit 信息、PR 描述、文档中不得出现真实 Token、密码、私钥、内部真实地址。
4. 凭证仅存储于本机对应服务的本地配置文件；不得写入环境变量提交记录、CI 日志或示例截图。

## 2. 权限最小化

- 各服务使用专用账号/Token；按最小权限发放。
- 默认只读；写操作（触发构建、投票、写评论、改 reviewer、创建/更新工单或页面）按需开放并在交互中二次确认。
- 提供只读模式开关（如 Jenkins）；高危操作可在配置中禁用。

## 3. 密钥扫描与 CI 拦截

- CI 启用密钥扫描（gitleaks 或等效规则），发现疑似 Token/密码即阻断合并。
- PR 检查项包含：本地配置/凭证/日志/PID/依赖目录未被提交。
- 若历史提交中误入凭证，应视为已泄露：立即在对应系统重置凭证，并清理提交记录后强推，同时在问题记录中登记。

## 4. 网络边界

- 主路径仅访问内网/本地可达实例；不将凭证或内部地址外泄到第三方托管服务。
- 不使用计划外的外部远程 MCP 桥接端点；确需使用须先在架构决策记录中登记。

## 5. 审计与留痕

- 记录启停、配置变更、连通测试结果；审计日志不含敏感值。
- 过程问题与变更分别登记到 `docs/operations/问题记录.md` 与 `docs/operations/更新记录.md`。

## 6. 暴露处置

- 一旦凭证在聊天、截图、提交记录、第三方渠道暴露：立即重置 → 登记问题记录（编号、来源、时间、处置）→ 确认新凭证仅存本地。
